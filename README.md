# Alejandro Ucan-Puc - Academic Website (Pelican)

This repository contains a Pelican static site for an academic homepage with sections for:

- About me
- Research (projects + ORCID-backed publications)
- Courses (including reveal.js slides)
- Repositories and learning notes (GitHub API + manual curation overrides)
- Undergraduate Seminar in Data Science (embedded YouTube videos)
- Blog (popular science)
- Contact

## 1. Quick Start

From the project root:

```bash
make publish
```

Then preview locally:

```bash
python3 -m http.server 8000 --directory output
```

Open:

- http://localhost:8000/

If port 8000 is busy, use another port (for example 8001):

```bash
python3 -m http.server 8001 --directory output
```

## 6. ORCID Auto Sync (Research Overview + Publications)

The build automatically runs:

- `scripts/sync_orcid.py`

This script rewrites:

- `content/pages/research/index.md`
- `content/pages/research/publications.md`

Default ORCID is configured in `Makefile`:

- `ORCID_ID ?= 0000-0002-0037-9394`

To use a different ORCID for one run:

```bash
make publish ORCID_ID=0000-0000-0000-0000
```

Important:

- Do not manually edit `research/index.md` or `research/publications.md` unless you also change `scripts/sync_orcid.py`, because the next build will overwrite those files.

## 7. GitHub Auto Sync (Repositories + Learnings)

The build automatically runs:

- `scripts/sync_github.py`

This script rewrites:

- `content/pages/repositories/index.md`

Manual curation and ordering live in:

- `content/extra/github_repositories_overrides.json`

The overrides file supports curated ordering (`featured_repositories`, `featured_forks`), optional exclusions (`exclude_repositories`), and editable notes (`learning_log`).

Default GitHub username is configured in `Makefile`:

- `GITHUB_USERNAME ?= alxcn`

To use a different username for one run:

```bash
make publish GITHUB_USERNAME=your-github-handle
```

Important:

- Do not manually edit `repositories/index.md` unless you also change `scripts/sync_github.py` or the overrides file, because the next build will overwrite the page.

## 11. Deploy to GitHub Pages

GitHub Actions workflow:

- `.github/workflows/deploy.yml`

On push to `main`, the workflow builds and deploys automatically.

Canonical URL strategy:

- Default production canonical URL is set for GitHub Pages project sites:
  - `https://alxcn.github.io/alejandroucanpuc`
- You can override canonical URL with an environment variable:
  - local build: `make publish SITE_CANONICAL_URL=https://your-domain.example`
  - CI build: set repository variable `SITE_CANONICAL_URL`
- If `SITE_CANONICAL_URL` is not set in CI, workflow fallback is:
  - `https://<owner>.github.io/<repo>`
- If you switch to a custom domain, set `SITE_CANONICAL_URL` to the full custom domain URL.

## 12. Quality gates in CI

Before deployment, CI now enforces:

* `make publish` (production build)
* Markdown linting (`markdownlint-cli2`)
* HTML validation (`html-validate`)
* Broken-link checks (`lychee` against generated output)
* Image size budgets (`scripts/check_image_budgets.py`)

Deployment only runs after these checks pass.

### 12.1 Run the same checks locally

```bash
make publish
npx --yes markdownlint-cli2 "content/**/*.md"
npx --yes html-validate "output/**/*.html"
python scripts/check_image_budgets.py output/images --max-file-kb 450 --max-total-kb 1600
```

No extra secrets are required for the deploy workflow.

## 12.2 External sync resilience (ORCID/GitHub)

Build steps that sync ORCID and GitHub content now include fallback behavior:

- If ORCID API is temporarily unavailable, `scripts/sync_orcid.py` keeps the existing generated research pages when present.
- If GitHub API is temporarily unavailable, `scripts/sync_github.py` keeps the existing generated repositories page when present.
- If there is no prior generated content to reuse, the scripts fail clearly so the issue is explicit.

This makes routine builds less brittle while still surfacing first-run failures.
